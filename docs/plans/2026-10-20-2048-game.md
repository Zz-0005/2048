# 2048 Web Game — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [x]`) syntax for tracking.

**Goal:** Build and test the approved PRD-2048 v2.0 game as a static, dependency-free web app (index.html + styles.css + script.js) with a pure, unit-tested rule engine and a real-browser E2E suite.

**Architecture:** One IIFE module (`script.js`) in two layers. Layer A is a pure engine (board maths, move/merge, session state machine, RNG injection, storage adapter, event emitter) attached to `globalThis.Game2048` and `module.exports` — importable by Node tests with no DOM. Layer B is the DOM renderer/input controller, initialised only when `document` exists, so engine tests stay pure. `index.html` owns semantics/ARIA, `styles.css` owns layout/theme/motion.

**Tech Stack:** Browser ES2020 (no framework, no build step), Node 24 built-in `node:test` for unit tests, `playwright-core` driving installed Microsoft Edge for E2E.

## Global Constraints

- Deliverables at project root: `index.html`, `styles.css`, `script.js`; static hosting; `backend: none`.
- Default language zh-CN. Buttons are exactly `新局`, `继续游戏`, `重新开始`. All copy lives in one `STRINGS` object.
- Storage: `bestScore` (P0, integer, all access in try/catch). `gameState` restore is **not** delivered (D-003 default when undecided); nothing in the UI may claim "关闭后继续".
- Board is always 16 cells; every non-empty tile is a power of two ≥ 2.
- Move algorithm: read from the movement side → compact zeros → merge adjacent equal pairs once → pad zeros; score += merged value; one new tile per valid move only.
- Invalid move changes nothing: board, score, moves, and RNG state.
- 2048 triggers `win_pending` only the first time per game; `继续游戏` → `playing_after_win`; win is evaluated before loss in the same move.
- Touch: max-axis displacement ≥ 24px; `major/minor < 1.5` means diagonal → ignored; short touch and multi-touch ignored; board has `touch-action: none` and `overscroll-behavior: contain`.
- `Esc` closes only the win overlay, keeps `win_pending` and the board unchanged, and never triggers continue/new game. Backdrop click never closes an overlay.
- Animations 100–200ms, never block input; `prefers-reduced-motion: reduce` disables non-essential motion.
- Events: `emit(name, payload)` with whitelisted fields only — `game_start, move, merge, game_win, game_over, restart, storage_error`. No PII, no free text. Event failures never block play.
- A11y: `role=grid` / `role=gridcell`, `aria-live` announcements, readable overlay names, focus moves to primary button on open and returns to the trigger on close, visible focus ring, AA contrast, no colour-only signalling.
- Layout from 320px, no horizontal scroll, safe-area insets respected.
- MIT LICENSE + attribution to Gabriele Cirulli + reference repo link; version string on the page.

## Review Focus

- **Rapid/key-repeat input during overlays or animation** — a reasonable player hammers a key; board, score and `moves` must never advance while `win_pending`/`game_over` is shown.
- **Storage holding garbage** (`"abc"`, `-5`, `1e9`, `null`, JSON) — the game must start normally and never render `NaN`.
- **Swipe that starts on the page but ends on the board** (and vice versa) — must not scroll or move unpredictably; only gestures starting on the board are handled.
- **Tile values far beyond 2048** (4096…131072) — layout must not overflow and merge scoring must stay exact.
- **Best score across tabs / reload with storage blocked** — never a blocking error dialog, never a lost playable session.
